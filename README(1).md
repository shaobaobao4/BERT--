# 20 Newsgroups 文本分类项目说明文档 (基于 BiGRU)

## 1. 项目概述
本项目基于 `20newsgroups` 数据集，针对 `alt.atheism` (无神论) 与 `soc.religion.christian` (基督教) 两个类别进行二分类任务。为了真实评估模型对文本语义的理解能力，数据加载时严格排除了 `headers`、`footers` 和 `quotes` 等可能导致模型“作弊”的元信息。本项目通过构建双向 GRU (BiGRU) 网络，结合精细的预处理与调参策略，成功使模型在测试集上的准确率稳定突破 0.70。

## 2. 模型结构设置方案
为了在有限的样本数据（约 1100 篇训练文本）上最大化提取有效特征并防止过拟合，本项目的模型架构 `GRUClassifier` 进行了如下针对性设计：

* **词嵌入层 (Embedding Layer, Dim=256)：** 将离散的单词索引映射为 256 维的稠密向量。256 维的空间足以捕捉宗教与无神论辩论中复杂的语义关系，相较于常见的 100 维，它能提供更强的特征表达能力。
* **核心特征提取层 (1 层双向 GRU, Hidden_Dim=256)：**
    * **选择单层 (Num_layers=1)：** 数据集较小，过深的网络容易导致严重的过拟合。单层网络足以胜任此量级的文本特征提取。
    * **选择双向 (Bidirectional=True)：** 文本情感和语义往往依赖上下文。双向结构让模型能同时“从前向后”和“从后向前”阅读，准确捕捉例如否定句或条件句的真实语义。
* **参数初始化策略 (Xavier Initialization)：** 代码中显式地对 GRU 的权重使用了 `nn.init.xavier_uniform_`。这是一种高级技巧，能有效保证模型在训练初期的前向传播和反向传播中，方差保持一致，防止梯度消失，大幅提升了模型收敛的下限。
* **全连接输出层 (Linear Layer)：** 接收双向 GRU 最后一个时间步的前向与后向拼接向量（维度为 256 * 2 = 512），输出最终的 2 分类逻辑回归结果。

## 3. 超参数选择与依据
模型的成功很大程度上依赖于以下超参数的精准组合：

* **最大词表大小 (`MAX_VOCAB_SIZE` = 10000)：**
    * **依据：** 宗教和哲学类文章通常包含大量的专有名词（如 theology, evolution）。10000 的词表大小既能确保保留这些高价值的区分性词汇，又通过截断低频词剔除了拼写错误带来的噪音。
* **序列最大长度 (`MAX_SEQ_LENGTH` = 300)：**
    * **依据：** 新闻组辩论文章普遍较长。设定为 300 可以在涵盖大部分文章核心论点的同时，避免过长序列造成的内存溢出和计算冗余。
* **批次大小 (`BATCH_SIZE` = 32)：**
    * **依据：** 在小样本学习中，如果 Batch 设得太大（如 128），每个 Epoch 的参数更新次数过少，模型难以学到细节；设为 32 增加了梯度更新的频率，有助于模型更快、更稳地寻找最优解。
* **随机失活比例 (`DROPOUT` = 0.3)：**
    * **依据：** 文本任务极易死记硬背训练集数据。在嵌入层之后和 GRU 拼接后施加 0.3 的 Dropout，每次训练随机屏蔽 30% 的神经元，强制模型学习全局上下文而非特定敏感词，同时 0.3 的比例也不至于像 0.5 那样阻断过多有效信息的传递。

## 4. 优化方法与防过拟合策略
针对文本分类任务的特性，我们采用了以下优化器配置和训练策略：

* **优化器选择 (Adam)：**
    * **依据：** 选用 `Adam` 优化器。其自适应学习率机制在处理 NLP 中稀疏的词频分布时表现极佳，收敛速度远超传统的 SGD。
* **学习率 (`LEARNING_RATE` = 0.0005)：**
    * **依据：** 弃用了默认的 0.001，改用偏小的 0.0005。较低的学习率配合较多的轮数（40 轮），能让模型在误差平原上走得更稳，防止在接近最低点时发生剧烈的准确率震荡。
* **L2 正则化 (`WEIGHT_DECAY` = 5e-4)：**
    * **依据：** 这是极其关键的防过拟合策略。在优化器中加入权重衰减，相当于在损失函数中加上了参数的平方和惩罚项，抑制了神经元权重的异常膨胀，显著提高了模型在测试集上的泛化能力。
* **最佳模型保存 (Best Model Checkpointing)：**
    * **依据：** 模型在 40 轮的训练中，可能会在中间某几轮达到最佳状态，随后进入轻微过拟合。代码在每一个 Epoch 结束后都会计算验证集准确率，并仅保存验证集准确率最高时刻的模型权重（`best_model.pth`）。最终测试时，加载该最佳模型，确保测试结果反映的是模型的“巅峰实力”。
